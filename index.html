The signal game

Players. Each signalised junction is one rational agent. A 2×2 grid has 4 players, a 3×3 grid has 9.

Strategies. Player i picks which road gets the green next: ↕ North–South or ↔ East–West.

Payoff. The player gains for every vehicle it can clear, and for waiting time it stops from piling up. It loses for switching (lost time), for pushing cars into a neighbour whose queue is already full, and it gains when a neighbour is about to send it a platoon on the same road.

ui(ai, a−i) = Σk∈ai ( qk + 0.4·mk + ω·wk/30 )  −  σ·1[ai ≠ current]
      − λ Σj∈down(i,ai) qj←i·(1 − 0.7·1[aj = ai])  +  κ Σj∈up(i,ai) 0.6·qj→i·1[aj = ai]

q = stopped vehicles near the stop line, m = vehicles still approaching, w = total time the queue has waited, σ = switching cost, λ = penalty for spilling into a neighbour, κ = bonus for green-wave coordination.

Equilibrium. The signals run best-response dynamics once per second: each junction in turn picks its best action given the others' current choice, until nobody wants to change. That fixed point is a pure-strategy Nash equilibrium: no junction can do better by changing its own phase alone. Safety rules still apply: minimum green 8 s, maximum green 45 s, 2.5 s yellow, 1 s all-red.

Selfish = the same game with λ = κ = 0, so each junction ignores its neighbours. Fixed-time = a 20 s / 20 s timer.

Run history

1. Problem statement

Complex Engineering Problem, option 1: Smart Traffic Signal Optimization using Game Theory. Design and implement a multi-agent traffic management system where each traffic signal acts as a rational player competing for green-light allocation, to minimise overall congestion and vehicle waiting time.

Objectives

  • Model each signalised junction as a rational agent with a strategy set and a payoff function.
  • Find each decision as a Nash equilibrium of the resulting non-cooperative game.
  • Build a microscopic traffic simulator to test it, and compare against fixed-time and non-cooperative (selfish) control.
  • Evaluate with data-science methods: repeated runs, common random numbers, confidence via paired t-tests.

2. System model

Road network

An N×N grid of junctions (N = 2 or 3), connected by two-way roads with one lane per direction, left-hand traffic. Vehicles enter at the 4N border roads by a Poisson process with a configurable rate and East–West / North–South mix, and leave at the far border. About a quarter turn left or right at each junction they cross.

Vehicles

Cars, two-wheelers, auto-rickshaws and buses with different lengths and speeds. Each vehicle follows a leader-based rule: it accelerates toward its desired speed but never faster than √(2·b·d), where d is the free distance to the vehicle ahead or to the stop line. Vehicles never block the junction box.

Signals

Two phases per junction: North–South green or East–West green. Switching goes through yellow (2.5 s) then all-red (1 s). Minimum green 8 s, maximum 45 s. Decisions are taken once per simulated second.

Assumptions and units

1 px ≈ 0.3 m, free speed ≈ 45 px/s ≈ 49 km/h, step Δt = 0.1 s. Demand is synthetic, not calibrated to a real city.

3. Game-theoretic controller

The game is Γ = ( N, {Ai}, {ui} ) with players N = junctions, actions Ai = {N–S, E–W} and payoff ui as shown on the Game model tab. Payoffs depend on neighbours' actions through spillback and platoon coordination, so the game is genuinely coupled.

  1. Read detector data: queue q, approaching flow m and accumulated waiting w for each of the four approaches.
  2. Start from the current phases. Junctions already in yellow or all-red are committed to their next phase.
  3. Sweep the free junctions. Each picks its best response to everyone else's current action (ties keep the current action).
  4. Repeat until a full sweep changes nothing. That profile is a pure Nash equilibrium (best-response cycles are cut off after 8 rounds; in our test runs every decision reached equilibrium).
  5. Apply the profile subject to minimum green, maximum green and yellow/all-red safety timing.

Because payoffs are built from congestion terms, best-response dynamics behave like a congestion-style game and settle quickly (typically 2 rounds), which is what makes it cheap enough to run every second. This is an empirical observation for this payoff design, not a proof.

Baselines

  • Fixed-time: 20 s N–S, 20 s E–W, no sensing.
  • Selfish adaptive: the same payoff with λ = κ = 0. Each junction maximises only its own local benefit and ignores neighbours.

4. Dynamic features (version 2)

The first version was a fixed demonstration. Version 2 lets the audience change the world while it runs, and measures how each controller copes.

  • Blocked approach (incident). A stalled vehicle or road work closes one approach of a junction for 60 to 180 s. Detectors let the adaptive controllers see the blockage, so they stop spending green on it, and the spillback penalty makes upstream junctions hold traffic back. Fixed-time cannot see it and keeps giving green to an empty stop line.
  • Ambulance with preemption. An emergency vehicle enters the network. For the adaptive controllers, an ambulance waiting on a phase adds a large term to that phase's payoff and shortens the minimum green to 3 s; the usual 2.5 s yellow and 1 s all-red still apply. You can switch preemption off to see the difference.
  • Exact equilibrium analysis. Each second the simulator enumerates all 2F joint plans of the free junctions, counts the pure Nash equilibria and finds the plan with the largest total payoff, so the quality of the equilibrium that best-response dynamics found is measured, not assumed.
  • Signal timeline. A time-space view of every junction's phase for the controller on the map.
  • Benchmark with disruptions, CSV and JSON export, a saved run history, and a λ sweep that finds how much neighbour-awareness pays.
  • Shareable scenarios. The page address encodes the grid, load, seed and game weights. Copy it with the Share link button to reproduce a run exactly.

5. Metrics

  • Average delay per vehicle (s): trip time minus free-flow time, over all vehicles including those still waiting.
  • P95 delay: the delay that 95% of vehicles stay under (fairness / worst case).
  • Vehicles stopped: network-wide time average of vehicles below 2 px/s.
  • Stops per trip and throughput (completed trips per minute).
  • Idling time (vehicle-hours) and an illustrative CO2 estimate: stopped vehicle-seconds × an assumed 0.8 L/h idle fuel burn × 2.31 kg CO2 per litre of petrol. A rough indicator, not a measurement.
  • Ambulance trip time (s): from dispatch to leaving the network.
  • Equilibrium efficiency: (total payoff of the chosen profile − worst profile) ÷ (best − worst), averaged over decisions.

Experimental design

Common random numbers: for a given seed all controllers see identical arrival times, vehicle types and turning choices, so differences come from the controller alone. Results are averaged over seeds and compared with a paired two-sided t-test.

6. What the results show

  • Over 10 seeds of 15 simulated minutes, adaptive control (selfish or Nash) cut average delay by 8% to 63% against the fixed timer across six scenarios, and every paired t-test had p < 0.001. The gain is largest when one direction is much busier (East–West +45%: 63%) and smallest under heavy load and in the rush-hour wave, where the network is close to saturation.
  • The coupled Nash game was not significantly better than the selfish controller in any scenario (−3.2% to +0.5%, p between 0.14 and 0.90). Most of the gain comes from reacting to queues at all. What the game formulation adds is an explainable decision rule, an equilibrium that can be checked, and a natural place for preemption and incidents.
  • Ambulance preemption cut the mean ambulance trip from 43.1 s (same controller, preemption off) to 31.8 s, against 50.1 s for fixed-time.
  • Very large λ makes junctions over-cautious and increases delay (on the 2×2 grid, 25.3 s at λ = 0 to 29.6 s at λ = 3).

Run the Benchmark tab yourself for exact numbers in any scenario. They are computed live, not pasted. The full table is in the written report and is reproduced by node tests/experiments.js.

8. Limitations and future work

  • Single lane per direction, two-phase signals, no left-turn phases or pedestrians.
  • Synthetic demand and a simplified car-following model. It is not calibrated against real detector data or validated against SUMO.
  • Small grids. Larger networks and heterogeneous link lengths are the natural next step.
  • Extensions: reinforcement-learning agents to learn payoff weights, Bayesian games with uncertain demand, emergency-vehicle priority, and calibration on real city data.

9. Likely viva questions

How good is the equilibrium your signals find? Could a better joint plan exist?

Often yes, and we measure it. The Game model tab enumerates every joint plan (16 for a 2×2 grid, up to 512 for 3×3), marks the Nash equilibria and the best total-payoff plan. Over 10 seeds of 15 simulated minutes, best-response dynamics found the very best joint plan in 57% to 84% of decisions (more often on the small grid) and on average reached 97% to 98% of the range between the worst and best plan. The pure equilibrium was almost always unique (1.03 to 1.20 per decision). The remaining gap is the price of anarchy of this game in practice.

How does the ambulance get priority without breaking safety?

Preemption only changes when the controller is allowed to start a change: the minimum green drops from 8 s to 3 s for the phase that is holding the ambulance back. Yellow (2.5 s) and all-red (1 s) are never skipped, so conflicting greens are impossible.

Why is this a game and not just an optimisation?

Each junction controls only its own phase but its payoff depends on neighbours' phases (spillback and platoon arrival). That interdependence with decentralised decision makers is exactly a non-cooperative game.

What is the equilibrium concept and why does it exist here?

Pure-strategy Nash equilibrium: no player gains by unilaterally changing its phase. In a finite game a pure equilibrium is not guaranteed in general, so we run best-response dynamics with an 8-round cap and report how often it converges. In the simulations it converges essentially always, because the payoff is built from congestion-style terms.

Why can Nash control beat the selfish one by only a little?

Selfish control already reacts to queues, which is most of the benefit over a fixed timer. The coupling terms only matter when neighbouring links are close to full, so gains show up under heavy load.

How do you know the improvement is real and not luck?

All controllers see identical traffic per seed (common random numbers), we repeat over several seeds, and use a paired t-test. The benchmark tab prints the p-values.

How did you keep the comparison fair?

Delay includes vehicles still on the map and those waiting to enter, so a controller cannot look good by leaving cars outside the network. Safety rules (yellow, all-red, minimum green, no blocking the box) are identical for all controllers.

Is it safe? Could two directions get green together?

No. Only one phase per junction can be green, a yellow and an all-red interval separate phases, and the simulator logs zero stop-line crossings against a red signal in test runs.
